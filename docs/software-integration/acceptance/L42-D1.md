# L42-D1：业务后端建井恢复与一次性版本登记

日期：2026-10-06。承接 [L42-C](L42-C.md)，本卡交付内部 Java 工作流，不增加公开 HTTP 建井接口，不宣称网页建井功能已完成。

## 实现

- `WorkerTemplateCreationClient`：仅使用配置的 Worker 地址和固定创建/查记录/下载路由；不接受用户输出路径、脚本或下载 URL，不跟随重定向。同步创建超时覆盖默认求解预算加30秒；读取和下载使用配置读取超时，包含响应体停滞时间。记录上限2MiB，工程上限64MiB；下载核对记录中的准确长度与SHA-256。
- `TemplateCreationJobStore`：独立创建表保存项目、稳定UUID、输入指纹、完整请求、Worker记录及登记版本。相同ID/项目/按字段排序的相同JSON输入只认领一次；项目或输入变更拒绝。未知响应持久为UNCERTAIN，重启或重试只查询，不自动重复POST。JSON数值表示变化可能保守拒绝，调用方应原样保留请求。
- `TemplateCreationWorkflow`：首次认领才调用创建；响应丢失、解析失败或落库失败后保留不确定状态。恢复读取真实Worker记录。成功工程经哈希验证，复用既有上传服务登记，不另建模型存储路径。
- 登记时按项目行、创建行的顺序加数据库锁。上传和创建来源绑定加入同一事务；核对真实版本归属和工程哈希后才绑定版本ID。重复登记返回已绑定ID。新版本仍为UPLOADED，须提交后模型校验才能READY；不把建井原生成功冒充平台模型验收完成。
- 为上述事务复用补齐已有上传保护：按最大版本号分配、独占目录、不覆盖遗留目录、回滚只清理本次拥有的目录、校验队列在提交之后执行。暂存中不包含其他轨迹状态/公共界面改动。
