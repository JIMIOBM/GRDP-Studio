## 二、原平台链路（实证来源）

结论来自**原平台部署容器的前端产物**（`grdp-web` 的 JS：`wellCluster.vue`、`dynamicPrediction.js` API 层、参数编辑页 `wellInput`）与**后端 Go 二进制**（handler/logic 符号与 JSON tag），非推断：

| 步骤 | 接口 | 关键点 |
|---|---|---|
| 默认名称 | `GET /projectanalysis/dynamicprediction//{p}/{g}/2/defaultname` | 井组 `predictionType=2`；路径保留双斜杠 |
| 创建任务 | `POST /projectanalysis/dynamicprediction` | `dynamicPredictionType: 2`（1=气藏/2=井组/3=单井）、`wellNames` 多口、`productivityEvaluationForm`（1=压力形式/2=压力平方形式/3=拟压力形式）；原平台弹框要求**至少 2 口井** |
| 任务详情 | `GET /projectanalysis/dynamicprediction/{p}/{g}/{id}` | `reservoirInput`（总体参数 21 字段）+ `wellInputs`（各井参数，平台自动带出） |
| 启动预测 | `POST /projectanalysis/dynamicprediction/Calc` | body = `{projectId, gasReservoirId, dynamicPredictionId, reservoirInput}`（井组用通用 Calc；单井版是 `/{wellName}/Calc`） |
| 绘图 | `GET /projectanalysis/dynamicprediction/result/wells/chart/{p}/{g}/{id}` | 井组 `type=wells` 且**不传查询参数**（单井 `type=well` 附 `wellName` 任务名）；`chartItems` 与单井同构，井组含 4 个输出序列：气产量、累产气量、地层压力、采出程度 |

`reservoirInput` 字段（参数面板可编辑项与未展示字段的清单）：`targetProduction, externalWellheadPressure, predictionStartTime, predictedTimeStep, predictedTimeStepNumber, economicLimitGasProduction`（面板可编辑）+ `specificGravity, hydrogenSulfide, carbonDioxide, nitrogen, originalFormationPressure, formationTemperature, waterSaturation, rockCompressionCoefficient, waterCompressionCoefficient`（面板可编辑，分组折叠）+ `gasType, modificationMethod, deviationFactorMethod, viscosityMethod, mbEquationType, productivityEvaluationForm`（未展示，**原样从详情带回**，不猜测编码）。

`predictionStartTime` 语义：显示日期的 **UTC 零点毫秒**（原平台参数页 `new Date('YYYY-MM-DD')`，与单井版 HAR 一致）。

## 三、实现逻辑

### 1. 页面接入

库级功能走完整 URL 定位（可刷新/可回退）：`/ipr?scope=reservoir&projectId&gasReservoirId&storageId&group=协同预测&parent=一体化耦合优化&feature=单目标|多目标`，由 `ReservoirWorkspaceContent.vue` 分发到本组件。井列表取库成员井 `storageCatalogApi.wells`（与井间对比一致），默认全部参与。

### 2. 任务准备（进页面自动）与「启动预测」（组件 `ensureTaskPrepared` / `startPrediction`）

**参数不需要手工输入**：与原平台"新建井组动态预测 → 参数页"一致，进入页面（默认名称与成员井就绪）后自动完成一次"准备"：

```
进页面（切库/切模式/换记录重置后）
  ├─ 并行：loadWells（成员井，默认全选）+ loadDefaultName（平台顺延默认名称；
  │        从记录打开时跳过，名称由记录覆盖）
  ├─ 查本项目留存表（GET /prediction-results，记录的唯一数据源）：
  │    ├─ 从记录打开（URL predictionId）→ 必须命中留存记录 → 载入该任务：
  │    │    GET 任务详情 → 井勾选同步为任务实际井集 → 回填参数面板
  │    │    → GET 绘图显示平台上已有曲线（不触发重新计算）
  │    ├─ 否则载入本模式最近留存的记录（列表按最近保存在前，同上）
  │    └─ 没有留存记录 → 不自动创建（避免刷新堆积），提示从目录「新建预测」开始
  └─ 状态提示"已载入（本模式最近的）预测记录… / 当前还没有本模式的预测记录…"
```

准备失败（如未登录）不阻断页面，点击「启动预测」时会重试创建。任务创建后**预测名称与产能方程形式固定**（与原平台一致，二者只在创建时生效）。

**原平台唯一约束**（实测确认）：`dynamic_prediction` 表的唯一键为「项目+气藏+名称+类型」——同名任务会返回"分析已存在"。因此：改井选择后创建新任务前，先用平台顺延名称替换本会话已占用的名称；创建失败（消息含"已存在"）也会自动换名重试一次，不会把"分析已存在"抛给用户。

用户（可选）修改参数后点"启动预测"：

```
点"启动预测"
  ├─ 校验：井数 ≥ 2；全部面板字段数值校验
  ├─ 会话内无任务（准备失败重试）或 井集合变化 → POST 创建任务（新任务回填参数）
  ├─ 组装 Calc：详情未展示字段原样带回 + 面板值覆盖（空值不覆盖）
  ├─ 计算前取绘图指纹（新任务无曲线 → 记为 empty）
  ├─ POST Calc → 轮询 /result/wells/chart（8 次 × 1.2s）
  │    指纹变化（或计算前为空）→ 判定为本次计算的新曲线
  └─ 渲染双轴图 + 状态文案；Calc 5xx/超时时只要核实到新曲线仍展示并警告
```

**参数覆盖保护**：用户改过面板后（`panelTouched`），重新拉取的平台默认值不再覆盖用户编辑；井选择变化触发的新任务只更新任务与详情，不动面板已有值。

- **任务生命周期**：进页面复用**本模式最近留存**的记录（刷新不堆积）；没有留存记录时**不自动创建任务**（避免刷新页面堆积平台任务），提示点击目录「新建预测」开始。会话内复用同一任务（改了参数再点"启动预测"= 对同一任务重算）；更改井选择会在启动预测时自动创建新任务（名称取平台顺延值），留存成功后归入本模式目录。任务本身仍可在原平台「工程管理-分析结果-动态预测-井组动态预测」下查看管理（与页面记录目录相互独立）。
- **新建预测**：目录里「单目标/多目标」下固定展示「新建预测」动作节点（位于记录列表顶部）——点击取平台顺延名称（如平台已存在到"井组动态预测 12"，新建即"井组动态预测 13"）按当前井选择创建新任务；**启动预测并留存成功后**该预测才会出现在记录目录（新建动作本身不产生记录）。用户改过的面板参数保留、未改的回填新任务的平台默认值。连续点击可连续创建。实现：动作节点 → `requestNewCouplingPrediction`（一次性意图，见 workspaceTreeState）→ 页面组件已挂载时立即消费执行，跨页面进入时由 `ensureTaskPrepared` 统一消费。
- **绘图确认**：计算前先取曲线指纹；只有指纹变化（或计算前明确为空）才认定新结果，避免把任务里的历史曲线误标为本次计算（与"方案生成"同一策略）。
- **预测记录目录**：见下节。

### 3. 预测记录目录（左侧「单目标 / 多目标」父目录）

- **目录结构**：库 → 协同预测 → 一体化耦合优化 → 单目标 / 多目标（父目录，同时仍是功能入口）→ [**新建预测**（动作节点，固定在顶部）, **预测记录**]。
- **记录来源**：**本项目数据库的留存表**（`GET /prediction-results`，见第 6 节）——只有**留存过结果**的预测才作为记录出现；平台上的历史旧任务**不迁移、不显示**（用户明确）。展开目录时懒加载（与损耗评价的记录模式一致，刷新不批量请求）。
- **归属**：直接用留存记录自身的 `mode` 字段（保存时写入），不依赖本机浏览器——换电脑、清缓存都不会丢；单目标的记录只出现在单目标目录，多目标同理。
- **打开记录**：点击记录 → URL 携带 `predictionId` → 页面按任务编号从留存表核对并载入（参数 + 平台已有曲线，不触发重新计算）；组件 key 含模式与任务编号，切模式/换记录都会重建并重新准备。
- **刷新直达记录地址**：目录尚未懒加载时先加载对应模式目录再高亮（`ensureCouplingRecordLoaded`）；**留存成功后**记录实时 upsert 进目录并高亮（目录已加载时立即可见）。

### 4. 单目标 / 多目标的差异

| 项 | 单目标 | 多目标 |
|---|---|---|
| 参数面板 | 优化目标 = 目标产量 | 优化目标 = 目标产量 + **井口外输压力 (MPa)** |
| 外输压力取值 | 沿用任务详情带出值（不在面板展示） | 面板值覆盖；首次由详情回填，可编辑后重算 |
| 输出曲线 | 气产量、累产气量（2 条） | 与原平台一致：**气产量、累产气量、地层压力、采出程度（4 条）** |
| 其余（链路、任务策略） | 完全一致 | 完全一致 |

### 5. 目标量判定（面板底部）

- **计算量** = 预测期**结束点累计气产量 − 起始点累计气产量**。井组结果数据自预测开始时间起（实测：任务 32 的 `prediction_start_time=2019-07-07`，结果日期 2019-07-07 ~ 2039-03-24 与 240×30 天步长吻合），首尾点即预测期，无历史段歧义；累计值缺失的端点自动跳过，有效点不足两个时不判定。
- **目标量** = 面板底部「目标量判定」区的输入框（`目标需求量 (10⁸m³)`，单位与图表右轴一致，仅用于本机判定，**不随 Calc 提交**）。
- **判定**：`累计差值 = 计算量 − 目标量`；`计算量 ≥ 目标量（含浮点容差）` → **✓ 满足需求量**，否则 **✗ 不满足需求量（差 xx）**。未输入目标量时仅显示计算量并提示输入；配色：满足绿、不满足红。
- 判定随曲线自动更新：启动预测出图、或从记录打开载入已有曲线后立即生效；目标量输入框与判定区在一次会话内保留输入。
- 纯函数 `evaluateTargetDemand`（`vue/src/utils/wellGroupPrediction.js`）实现，单元测试覆盖首尾差、缺失端点、空输入、恰好相等（浮点容差）等边界。
- **目标量口径说明（用户拍板：目标量用独立输入，不引用参数列表的"目标产量"）**：参数列表的 `targetProduction` 是预测的**计算输入**（实测任务 32：井组总产量恒定 15.1738 = 目标值，4 口井按 1.66/2.01/5.72/5.79 分配），用它判定输出属循环论证；且参数字段值与实际产量的换算因子为 **86400**（字段值 15.17 对应实际日产 ≈131 万 m³/d，三个任务交叉验证比值均≈1.0），与曲线数据口径不是一套，直接比较数值上对不上。

### 6. 结果留存（本项目数据库）

- **目的**：每次预测完成后，把结果另存一份到**本项目自己的数据库表**（`project_prediction_result`），不依赖原平台内部结果表；历史任务**不做迁移**（用户明确），只保留从本功能上线后的新预测。
- **表**：`backend/src/main/java/com/grdp/studio/predictionresult/PredictionResultSchemaInitializer.java` 幂等创建（跟随 StorageNetworkSchemaInitializer 模式，等 `project_storage` 就绪后建表）。字段：范围（project/gasReservoir/storage）、任务编号与名称、模式（单目标/多目标）、井名 JSON、起止日期、点数、逐日结果 JSON（气产量/累产/地层压力/采出程度）、Calc 参数快照、保存时间；唯一键 `(project_id, gas_reservoir_id, prediction_id)`。
- **接口**（`/prediction-results`，无 /api 前缀；前端经 vite 代理访问）：
  - `POST /prediction-results`：保存/覆盖（`ON DUPLICATE KEY UPDATE`，同一任务重算保留最近一次）；校验：范围必须存在（storageId 提供时与损耗记录同样核对归属，跨项目 404）、点数非空、模式枚举、日期合法。
  - `GET /prediction-results?projectId&gasReservoirId[&storageId]`：留存记录摘要（最近在前），供后续查询/导出。
- **前端调用点**：`startPrediction` 预测流程成功（拿到曲线数据）后 `persistPredictionResult`（`vue/src/api/predictionResult.js` + `buildPredictionResultPayload` 纯函数组装请求体）；**留存成功后该记录即时插入左侧目录并高亮**（目录数据源就是留存表）；失败只 `ElMessage.warning` 提示、不阻断展示，可再次启动预测重试。载入历史记录（显示平台已有结果）**不**触发留存。
- **删除预测记录**：目录记录右键 →「删除预测记录」→ 确认（明确提示不可恢复）→ **先删原平台任务**（DELETE /dynamicprediction/{p}/{g}，body 携带 predictionId，与原平台前端一致；404 视为已删继续清理）→ 再删本项目留存（DELETE /prediction-results，幂等返回删除行数）→ 摘除目录节点；若删除的正是当前查看的记录，同时去掉地址中的 predictionId 并按无该记录重新准备。

### 7. 结果渲染

右侧 ECharts，x 轴日期（time）：

- 单目标：气产量（左轴，10⁴m³/d，黄）+ 累产气量（右轴，10⁸m³，蓝）。
- 多目标：在原平台 4 个输出指标（`gasProduction`、`cumulativeGasProduction`、`formationPressure`、`reservoirRecoveryDegree`，对应 nodeType 72-75）基础上绘制 —— 气产量（左 1）、地层压力（左 2，MPa）、累产气量（右 1）、采出程度（右 2，%）；平台未返回的序列跳过绘制，其余照常。

`isDeleted` 点跳过、`0` 保留（停产值）、空值断线。图表容器 `aria-label` 记录当前绘制的指标集合（无障碍 + e2e 断言）。页签标题为 `库名-协同预测-一体化耦合优化-{单目标|多目标}-分析结果`。
